# Content Studio 下一阶段计划

## 一句话目标

把当前的“素材清单 + 基础 MP4 导出”升级为一个可审阅、可复现的本地视频渲染工作台：创作者能看见并修改每一个镜头、字幕和效果指令，再导出成片。

这不是重做剪映。Content Studio 的优势是把 Agent 教学视频里的视觉决策结构化：为什么在此刻放大某个节点、为什么高亮某次工具调用、这句旁白对应哪段录屏，都应可见、可编辑、可回放。

## 产品边界

### 本阶段要做

- 本地渲染；不要求显卡，也不要求订阅线上模型。
- 模板化文字卡、淡入淡出、局部放大、高亮框、旁白驱动的 BGM 压低。
- 可编辑镜头指令；每次导出使用的指令要随任务保存。
- 本地字幕时间轴，并逐步升级到本地语音识别的逐词/逐短语高亮。
- 为未来接入 AgentScratch 留出独立的执行轨迹交换格式。

### 本阶段不做

- 通用多轨非线性剪辑器、复杂关键帧动画或素材商店。
- 未经用户确认的敏感信息遮挡。
- 未授权 BGM 的搜集、下载或分发。
- 根据“审美”全自动决定镜头；自动建议必须可以修改和关闭。

## 架构原则

```text
内容任务 / 上传素材 / Agent 执行轨迹
             ↓
      Render Directive（可编辑 JSON）
             ↓
    Render Job（状态、日志、可取消）
             ↓
 FFmpeg + 本地字幕/分析引擎
             ↓
    MP4 + SRT + 导出清单
```

`Render Directive` 是下一阶段的核心数据模型。它不保存某个剪辑软件的私有工程文件，而保存项目自己的可读指令，例如：

```json
{
  "type": "focus.zoom",
  "beatId": "decision",
  "start": 34,
  "end": 42,
  "target": { "x": 0.61, "y": 0.42, "width": 0.24, "height": 0.18 },
  "label": "它选择调用 calculator"
}
```

## 里程碑 0：渲染基础设施

先解决当前同步导出不适合长视频的问题，再新增视觉效果。

### 交付

- `RenderJob`：`queued`、`rendering`、`completed`、`failed`、`cancelled` 五种状态。
- 前端显示进度、错误摘要、重新导出和取消按钮。
- 每次导出保存所用指令、FFmpeg 命令摘要、成片和 SRT 的文件清单。
- 三个导出预设：`预览 720p`、`发布 1080p`、`竖屏 1080×1920`。

### 验收

- 90 秒视频导出时页面不超时，用户可看到状态变化。
- 同一个任务、同一份指令重复导出，镜头顺序和时长一致。
- 导出失败不会覆盖上一个成功成片。

## 里程碑 1：模板化后期（下一次实现优先项）

让用户不进剪映，也能生成一条“可发布但朴素”的 Agent 教学视频。

### 指令类型

| 指令 | 第一版行为 | 用户如何控制 |
|---|---|---|
| `card.show` | 黑底/深色背景标题卡、集数和步骤标题 | 修改文案、颜色、起止时间 |
| `transition.fade` | 镜头之间 0.15–0.4 秒淡入淡出 | 开关与时长 |
| `focus.zoom` | 按矩形区域裁切、放大至全屏 | 拖拽框选或填写坐标 |
| `highlight.rect` | 高亮框、暗化其余区域、文字标签 | 颜色、标签、起止时间 |
| `audio.duck` | 有旁白时自动降低 BGM 音量 | BGM 文件、目标音量、开关 |

### UI

- 在每个分镜下增加“画面指令”折叠面板，而非隐藏在自动化黑箱中。
- 提供三个教学模板：`黑箱提问`、`工具调用`、`文件搜索与总结`。
- 增加低清预览导出按钮，先看节奏再出 1080p。

### 验收

- 用户不写代码，可为每个分镜添加、删除、调整以上指令。
- 使用默认模板可自动得到文字卡、淡入淡出和至少一个高亮镜头。
- 任何效果均能在导出清单中追溯到具体指令。

## 里程碑 2：本地字幕与旁白对齐

当前已支持可选的 `faster-whisper` 本地句级转写、时间点与文案人工修订，并在导出时优先使用已修订结果；未配置本地模型或识别失败时，仍回退到剧本分镜字幕。下一步再扩展 ASS 与逐短语高亮。

### 技术方案

- 以 `faster-whisper` 作为可选本地识别引擎，默认 CPU / INT8；模型首次使用时由用户明确下载并可选择删除。
- 导出词级时间戳；中文界面按“短语”高亮，避免逐个汉字跳动带来的阅读负担。
- 将识别结果与原剧本并列显示：创作者选择“以剧本为准”或“以录音为准”，再手动修订 Agent、Context、Observation 等专有词。
- 生成普通 SRT、ASS 样式字幕和逐短语高亮的 MP4 版本。

### 验收

- 断网后，已下载模型可完成本地转写。
- 创作者可以修订文字、分段和时间点，修订后重新导出。
- 识别失败不会破坏已有剧本字幕，能回退到当前基础字幕。

## 里程碑 3：Agent 轨迹驱动镜头（差异化能力）

Content Studio 保持独立项目，但接收一个项目无关的 `agent-run-trace-v1.json` 文件；不直接导入 AgentScratch 的运行时或数据库。

### 交换数据至少包含

- 事件：`context_ready`、`model_think`、`tool_call`、`tool_result`、`final_answer`。
- 节点与连线的画布坐标、时间戳、可展示标签。
- 录屏裁切区域与画布坐标之间的映射。

### 自动建议

- `tool_call`：放大工具名与参数。
- `tool_result`：高亮返回值和回写路径。
- `final_answer`：缩小回完整轨迹，加总结卡。

建议默认生成但绝不直接锁定；用户可以删除或改写每一个镜头指令。

### 验收

- 导入一次轨迹文件后，自动产生可编辑的镜头建议。
- 不依赖 AgentScratch 安装，其他符合格式的 Agent 应用也能生成镜头建议。
- 对“计算工具调用”案例，能自动产出至少一次节点放大、一次参数高亮、一次结果回写高亮。

## 里程碑 4：安全与智能辅助

### 先做可控能力

- 已实现手动矩形遮挡；支持模糊、纯色覆盖和马赛克，且默认关闭。
- 导出前在后期时间轴中显示遮挡规则与覆盖时段；下一步可补充多边形遮挡。
- 本地 OCR 或检测仅用于“建议可能有敏感信息的位置”，不可自动永久遮挡或自动删除素材。

### 后做辅助能力

- PySceneDetect 用于长录屏中的镜头变化建议；不用于替代分镜。
- 根据鼠标停顿、节点事件和旁白停顿建议切点。
- 由用户选择采纳，且保存建议来源。

## 依赖与许可证策略

- FFmpeg：继续作为本地渲染内核；发布桌面安装包前必须针对实际打包的 FFmpeg 构建审计 LGPL/GPL 组件与署名要求。
- faster-whisper / Whisper：优先选择 MIT 许可实现，保留许可证与模型来源说明。
- PySceneDetect：BSD-3-Clause，可作为可选分析依赖。
- BGM：软件只处理用户提供或确认可用的音频，不分发曲库。
- 每新增依赖，都更新 `THIRD_PARTY_NOTICES.md`；不复制大型开源剪辑器的代码。

## 推荐实施顺序

1. 里程碑 0：渲染任务与导出预设。
2. 里程碑 1：文字卡、淡入淡出、手动高亮框、BGM 压低。
3. 用自己的四个 Agent 教学案例连续生产 3–5 条视频，记录需要手工修正的步骤。
4. 里程碑 2：本地字幕与对齐；根据真实中文旁白校准体验。
5. 里程碑 3：定义并接入 `agent-run-trace-v1.json`。
6. 里程碑 4：手动遮挡，再考虑智能建议。

只有当“连续三条视频中同一个剪映手工步骤重复出现”时，才把它提升为 Content Studio 的自动化能力。
